# 解剖人形方向样例 02（未通过评审）

这是“用旧版肌肉人物画风重做坐姿轻抬膝”的实验版本，**没有接入正式课程，也没有发布**。

## 结论：不采用

独立视觉审查拿它和旧版素材（3D 渲染的灰白解剖男模）逐帧对比后判定：

- 仍是扁平矢量，读起来像“泥偶换了灰白配色”，不是解剖人形。
- 没有肌束走向、骨点、环境光遮蔽；股四头肌仍是一块平涂色。
- 脚没有足跟、足弓与脚趾体积，抬腿帧的离地间隙不足以让人读出动作。
- 头颈、肩、髋的衔接仍是示意级。

根因不是调色或微调能解决的：旧素材是 3D 渲染——顺着曲面走的肌纤维、沟里的连续遮蔽、同一角色换姿势。手写 SVG 无法复现这一层级，继续补细节只会得到“更精细的泥偶”。

## 保留价值

- `index.html` / `prototype.css` / `prototype.js`：单人大画面、学习与回合分离、抬腿按髋关节旋转、暂停同时停止动画与口令、减少动态、本机语音降级的可运行实现。
- 这套交互逻辑与视觉无关，可以复用到任何新的示范素材上（真人视频、3D 预渲染）。
- 几何参数集中在 `prototype.js` 的 `pose()` 与 `frames`，换素材时只需替换 SVG 或播放器。

## 验证

```sh
COACH_DIR=coach-anatomy node scripts/test-coach-prototype.mjs   # 25/25 通过
COACH_DIR=coach-anatomy COACH_PREFIX=anatomy node scripts/capture-coach-prototype.mjs
```

通过项包含：两种手机尺寸无横向溢出、暂停冻结计时与姿态、离页不补时、静态关键帧、减少动态、语音取消与四种降级、已打开页面离线交互、`file://` 直接打开、无存储写入与外部请求。

**未做**：iPhone 真机 / WebKit、真实语音听感、专业动作校对。人物为手写示意，不是真人或 3D 渲染。

## 后续路径

1. **3D 预渲染（最接近旧素材）**：本机已安装 Blender 与 ffmpeg，技术上可做；需要可商用的人体基础网格、绑定与逐动作调姿，并按 H.264 + 封面图接入播放器。
2. **真人短视频**：观感最好，需要拍摄或明确授权，并做专业动作校对。
